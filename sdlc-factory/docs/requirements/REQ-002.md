# REQ-002 — The free report is a public, shareable address that needs no account

- Priority: Must

## User story
As a founder who wants a colleague to see what AI says about our market, I want
to send them the report link, so that they see exactly what I saw without
signing up for anything.

## Rationale
The report is the product's only shop window: a person the founder sends the
link to must see exactly what the founder saw, with no account, session or
payment, and an address a stranger types by hand must always resolve to
something readable — a link that ends in a blank page or an error ends the
funnel at the first share. Because the report is a permanent public verdict
about somebody else's website, it must be reachable by the link and not by
search, and the report itself must tell the domain's owner how to prove they
control it and what that proof buys them — having the report corrected or having
it taken down — proof only whoever holds the domain can produce, because removal
is permanent and REQ-014 criterion 6 hangs an undisplaceable correction on this
same proof. Which kind of mail carries the confirmation link is REQ-064's, the
single home for the kinds of mail the product sends. Source: `BUILD.md` §3 (the public report path) and §4.1
(header module, "Copy link").

## Acceptance criteria
1. Given the report address for a domain, when a visitor with no session, no
   cookie, and no prior visit opens it, then the full report is readable without
   signing in or paying.
2. Given a visitor on a completed report, when they use the copy-link control,
   then the copied address renders the same report, with the same measurements
   and the same measurement date, for a different person on a different device.
3. Given a report address for a well-formed domain, when a visitor opens it
   directly, then what loads is always one of three readable things — a stored
   report, a scan in progress, or one written line saying why there is no report
   for them to read — and never a blank page, a 404, or an unhandled error.
   Which of the three a given visitor gets, and whether a scan starts, is
   REQ-001, REQ-012 and REQ-015's, not this requirement's.
4. Given a report address whose domain segment is not a well-formed public
   domain name, when it is opened, then one written line names what is wrong
   with it and the visitor is offered the landing field — never a blank page, an
   unhandled error, or a scan.
5. Given any report address, when a search engine or other crawler requests it,
   then the page tells it not to index the page, and no sitemap the product
   publishes lists any report address; the report stays reachable by its link to
   anyone who has it.
6. Given any report, when it renders, then it names how to prove control of that
   domain and what proving it allows — correcting the market the report measured
   (REQ-014) or having the report removed: the exact DNS TXT record to publish
   for that domain, the mailbox at that domain criterion 7's link would be sent
   to, and the address a request is sent to — all readable by a visitor with no
   account, session, or payment.
7. Given a request that only whoever controls a domain may make — removing its
   report, correcting it as the domain's owner (REQ-014 criterion 6), or making a
   removed domain scannable again — when it is judged, then it completes only on
   proof that the requester controls that domain: either the DNS TXT record
   criterion 6 named is observed published on that domain, or ReachKit sends a
   link to an address at that domain and that link is used, that address being
   the one criterion 6 named and never one the requester chooses. The address a
   request arrives from never proves control by itself. Proof once completed is
   a standing and not a single act: for 30 days afterwards the person who
   produced it may make any further request of this kind for that domain without
   proving control again, and every report of that domain they open in that time
   offers them what a proven owner may do (REQ-014 criterion 1); after 30 days
   the standing lapses and either route above restores it. The mail is sent once
   per request either way — a standing that persists is not a mail that repeats:
   that link is a mail the recipient cannot stop, sent only in answer to a
   request they made and never again unprompted.
8. Given a removal request completed under criterion 7, when it is granted, then
   within 5 working days the report is no longer readable at its address, and
   that address shows the removed report to nobody and starts no scan for anyone,
   on that visit or any later one — until a request completed the same way asks
   for that domain to be scannable again. In its place, one written line says the
   report was removed at the domain owner's request and names the address such a
   request is sent to, so the owner who changes their mind has the route back
   where they will look for it. No address is withheld this way for a domain
   whose owner has made no such request: a report is taken down only by a
   removal request completed under criterion 7, never at ReachKit's own
   initiative.
9. Given a stored report that no request under criterion 7 has removed, when its
   address is opened at any later time by anyone holding the link, then the same
   report is still readable there under the same address, carrying the
   measurement date it was stored with. No report link expires, is bound to the
   visitor who first opened it, or stops resolving with age; a stored report
   ageing only gains the re-scan control REQ-012 criteria 3 and 4 govern.

## Non-goals
- No private, per-visitor, or expiring report links — permanence is stated as
  criterion 9, not left to this list.
- No editing, annotating, or branding of a report by whoever shares it.
- No account, session, or email gate on any part of the report — the only trade
  is the finished page (REQ-010).
- No ban on a domain its owner has not asked to remove (criterion 8), and no
  route back other than the one criterion 8 names — removal is lifted only by
  the same proof of control that obtained it.
- No second proof of control elsewhere in the product: criterion 7 is the single
  home for what proving control of a domain means.
- The exhaustive mapping of every state a report address can be in — no stored
  report, failure cooldown, removed, free-path limit met — to what loads there:
  the blueprint's, derived from this requirement's promise that a report address
  never ends in a blank page, a 404 or an unhandled error, and from REQ-001,
  REQ-012 and REQ-015, which own when a scan starts.
- Which mailbox at a domain criterion 7's link is sent to: a membership set the
  blueprint holds. This requirement promises only that the requester never
  chooses it and that the report names it before it is used.
