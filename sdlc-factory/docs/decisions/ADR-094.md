# ADR-094 — LANDMINE — the free report's AI matrix sets `load_async_ai_overview`; `BUILD.md`'s own "never set it" line is now wrong

> **Read this before "fixing" `serpOrganic`'s free-matrix call back to
> `loadAsyncAiOverview: false`.** `BUILD.md` §6.2 says "Never set
> `load_async_ai_overview`" and §6.4's never-list names it explicitly, in
> writing. Restoring that literal reads as specification fidelity. It silently
> reintroduces the exact undercount the owner ruled against: an AI answer
> Google served asynchronously renders as "no AI answer," and the free
> report's stated denominator becomes false again.

- Date: 2026-09-03

## Context
`registry/evidence/RESEARCH-dataforseo-endpoints.md` §2.3, read against `BUILD.md`
§6.2 and §6.4 and against BP-008's own enforcement of the never-list: DataForSEO's
`ai_overview` item carries `asynchronous_ai_overview`, and its docs state
verbatim (quoted in full in the evidence file) that Google "frequently" serves an
AI Overview this way, that the default request only returns a cached one, and
that an asynchronous one is returned as `"ai_overview": null` unless
`load_async_ai_overview: true` is set on the request — at a cost of one extra
base price, refunded when the flag turns out to be unused.

`BUILD.md` §6.2 states, unconditionally: "Never set `load_async_ai_overview`."
§6.4's never-list repeats it as one of the calls BP-008's client may not make.
BP-008 enforced this by absence — no function on its surface could set the
flag — and REQ-006 criterion 2 ("that cell states that no AI answer appeared")
was accordingly silently false on any search where Google served an
asynchronous overview the product never fetched: an AI answer had appeared and
was rendered as though none had.

`OWNER-QUESTIONS.md` item 1 put the choice to the owner: pay the surcharge so
the card counts Google's actual AI answers, or keep the 0¢ rule and add a
disclosure that the card counts only answers Google had cached. The owner's
ruling, verbatim: "the free report loads asynchronous AI Overviews
(`load_async_ai_overview`), the cost stays inside the 12¢ cap; the card counts
Google's actual AI answers."

The worst-case cost is bounded and self-refunding (evidence §2.3, derived):
12 live SERPs at the surcharge rate is 4.8¢ instead of 2.4¢, taking the free
report's own total from BP-025's ~6.6¢ (decision 2, the two-nano-call reading)
to **~7.2¢ worst case** for that node's spend, comfortably inside `CAPS.FREE_C`
12¢. Nothing here is a promise the product cannot afford.

This spans three nodes and none of them owns it alone:
- **BP-008** enforces the never-list by absence and is the only place a flag
  can be admitted at all.
- **BP-007**'s `recordFetch` contract takes a fixed `costCents` per call, known
  before `run()` executes — a design that assumes every endpoint's price is
  fixed. This is the one endpoint whose actual vendor charge is data-dependent
  (1x or 2x the base price, decided by the vendor after the call), and the
  contract is not to change for it.
- **BP-025** is the only caller permitted to set the flag, and its NFR budget
  states the free report's cost envelope.

And it amends a written rule (`BUILD.md` §6.2/§6.4) rather than merely adding
to one, so under rule 2.2's sharpened form and the constitution's landmine
clause this is a standalone file, not an entry inside any of the three.

## Decision
1. **`serpOrganic`'s `loadAsyncAiOverview` parameter is required, never
   defaulted** — the same pattern BP-008 decision 2 already applies to `mode`,
   so a call site that has not decided is a compile error rather than an
   inherited default.
2. **Exactly one call site passes `true`**: BP-025's twelve-question free-matrix
   call (`phrase.ts`'s SERP fan-out, `src/lib/market/questions/`). Every other
   `serpOrganic` call site — the paid weekly/deep target-SERP battery (BP-050,
   BP-036) — passes `false` explicitly, unchanged. **This ruling is scoped to
   the free report only**, per the owner's own words ("the free report loads
   asynchronous AI Overviews"); extending it to the paid battery is a separate
   question this file does not decide.
3. **The cost seam ledgers the surcharge-inclusive price on every flagged
   call, unconditionally** — `recordFetch`'s `costCents` is set to the
   surcharge rate (2x the base price) whenever `loadAsyncAiOverview: true` is
   passed, whether or not DataForSEO's own response later refunds the
   difference. BP-007's interface is untouched: this is a choice BP-008's
   call site makes about what value to pass, not a new capability the seam
   needs. See the `rests-on` row above for why this cannot under-count spend.
4. **`no_answer` now means what it says.** With the flag set, a `null`
   `ai_overview` on the free matrix's SERPs is a confirmed absence, not an
   unfetched asynchronous one — closing the gap the evidence file's §2.3
   identified in REQ-006 criterion 2. BP-025's decision 4 records the call-site
   change and the NFR consequence.

## Alternatives considered
1. **Keep the 0¢ rule and disclose the limitation** (`OWNER-QUESTIONS.md`
   item 1's other branch) — this would have required a new customer-visible
   caveat on the card (a string, the owner's to write) stating that the count
   excludes answers Google had not cached. The owner did not take this branch;
   no REQ-006 text changes as a result of this decision.
2. **Set the flag on every `serpOrganic` call, free and paid alike** — rejected
   as broader than what was ruled. The owner's words name the free report; the
   paid weekly battery's own cost and accuracy trade-off (REQ-063's page
   verdicts read AI-citation tests off these same SERPs) is not this file's to
   decide and is recorded as an open question on BP-051 instead.
3. **Widen `recordFetch`'s `costCents` to accept a function of the response**
   (`costCents: number | ((payload: P) => number)`) so the ledger could record
   the vendor's actual, possibly-refunded charge — rejected: it changes BP-007's
   contract for every endpoint to accommodate the one endpoint whose price is
   data-dependent, and the conservative fixed-price ledgering in Decision 3
   achieves the same cap-safety without touching a seam eleven other functions
   already rely on being simple.

## Consequences
- BP-008's `serpOrganic` signature and one Error & edge behavior bullet change;
  its Decisions section gains one entry citing this file.
- BP-025's NFR budget and one Error & edge behavior bullet change to state the
  new worst case and the closed gap; its Decisions section gains one entry
  citing this file.
- BP-007 is not edited. Its fixed-cost-per-call contract stands, and this file
  is the record of why the one data-dependent endpoint does not need it
  changed.
- `BUILD.md` §6.2 and §6.4 are not edited here; the divergence from their
  written text is recorded in this file, which is where a reader restoring
  "spec fidelity" will find out why not to.
- **Cost of reversing:** trivial in code — one boolean at one call site — and
  that cheapness is the danger, exactly as ADR-060 states for its own landmine.
  Reversing it does not fail loudly: the free report keeps rendering, the cap
  is still respected, and the only symptom is that some fraction of "no AI
  answer" cells quietly go back to meaning "we did not check" on searches
  where Google served an answer nobody read.
