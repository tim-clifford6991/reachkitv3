## The 90-second hard ceiling (derived, rule 1.1)

REQ-003 criterion 5 stops measuring at 90 seconds. `BUILD.md` fixes 60 seconds
and no ceiling above it, so the ceiling is a derived parameter, not a
transcribed one.

Derivation: 60 seconds is the promise a visitor is held to (§11, "Free ≈60s
live"), and a ceiling equal to the promise would cut off any run that overran by
a single slow vendor call — turning a report that was one call from complete
into a truncated one. A ceiling of 90 seconds is a 50% overrun: it leaves room
for exactly one vendor call to answer slowly past the promise while still
bounding what any visitor waits, and it is short enough that the wait stays
inside the "abandons an unlabelled wait" window the requirement is written
against. The upper bound is behavioural, not technical — every second past the
promise is a second the visitor already believes the page is stuck.

Cost of reversing it: low. The ceiling is one pinned constant
(`00-project.md`, "`src/lib/config/constants.ts` | **Every** pinned number in
the specification", asserted by `tests/pins.test.ts`), and moving it changes one
criterion's number and one pin — no schema, no vendor contract, no
customer-visible string beyond the written line REQ-003 criterion 5 already
requires.
