# WO-234 — verifyLive() — four outcomes as Measured<boolean>, never inferred from each other

- Branch: wo/WO-234-verify-live
- Estimate: ≤1 day

## Goal
Ship `verifyLive()`: fetch the page's own live address once, 24 hours after it published, and record reachable, indexable, in-sitemap and AI-readable as four `Measured<boolean>` values that are never guessed.

## File plan

> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/verify/verify.ts` | NEW | `CheckId`, `VerifyResult`, `verifyLive`. The four checks: `reachable` — one `safeFetch` GET of `live_url`, a 2xx with a non-empty body is true, any other status or transport failure is false with the status recorded internally, **a redirect to a different host is false and is not followed** (a page only reachable somewhere else is not reachable at the address we reported). `indexable` — true when neither the response's `X-Robots-Tag` nor the document's `<meta name="robots">` marks it against indexing; **both are checked, because either alone can be the one that is set**. `sitemap` — one `safeFetch` of `https://content.{sites.domain}/sitemap.xml`, true when the page's own address is listed. `aiReadable` — the same fetch as `reachable`, with no script execution of any kind, true when `bodyCoverage(html, drafts.body_md) ≥ VERIFY.coverageFloor`. **A page that is unreachable records the other three as `unmeasured` with the reason, never as `false`.** `verifyLive` never throws for a failing check and never retries one; a failure of the *job* writes nothing and leaves the row due. Writes only `publications.verify`. |
| `tests/publish/verify/verify.test.ts` | NEW | Each check true and false from its own fixture; an unreachable page records the other three as `unmeasured` and never as `false`; a redirect to another host is `reachable: false`; an `X-Robots-Tag` alone and a meta tag alone each make `indexable` false; a failing check does not throw and is not retried; a job failure before any check completed writes nothing and leaves the row due; the request carries `VERIFY.userAgent` and **never one of the six named AI agents**. |

**Exposes** — copied exactly from BP-049's `## Public interface`:

```ts
// src/lib/publish/verify/verify.ts
export type CheckId = 'reachable' | 'indexable' | 'sitemap' | 'aiReadable'

export interface VerifyResult {
  reachable:  Measured<boolean>
  indexable:  Measured<boolean>
  sitemap:    Measured<boolean>
  aiReadable: Measured<boolean>
  checkedAt: Date
}

export function verifyLive(publicationId: string): Promise<VerifyResult>
```

**The user agent is our own token.** BP-049 states it plainly: it is permitted
because the robots document BP-047 serves blocks no general crawler (REQ-059
criterion 4), **it is not one of the six named AI agents, and impersonating one
of them would be a false statement to a server we are measuring.** `VERIFY.userAgent`
is a pin in BP-005 and a test asserts it matches none of `AI_CRAWLERS`.

**The four outcomes are `Measured<boolean>`, not booleans** (BP-049 decision 1).
`boolean | null` reads as false in every language the surface will pass through,
and the reason a check did not run would be lost. Nothing anywhere defaults a
`Measured<boolean>` to `false`.

## Steps
1. Create `verify/verify.ts` with the block above verbatim.
2. Implement the four checks exactly as BP-049 states them. Do not infer one from another: an unreachable page records three `unmeasured` values with a reason.
3. Do not follow a redirect to a different host; record `reachable: false`.
4. Check both the header and the meta tag for indexability.
5. Run the `aiReadable` fetch with no script execution of any kind and with `VERIFY.userAgent`. Never send one of the six named AI agent strings.
6. Write `publications.verify` as the four serialised `Measured<boolean>` values plus `checkedAt`. Write nothing on a job failure.
7. Write the "an unreachable page does not record the other three as false" test first and watch it fail against an implementation that defaults them (constitution §8).
