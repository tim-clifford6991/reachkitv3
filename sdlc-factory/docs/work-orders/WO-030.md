# WO-030 — Fonts, the type scale and the numeral rule

- Branch: wo/WO-030-fonts
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-030.html
- Signed-off: <date>

## Goal
Self-host the two fonts and make the numeral rule mechanical: every numeral,
date, URL, search query and code-like string renders in JetBrains Mono with
`tabular-nums`.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW under BP-018's `code:`
glob `src/ui/**`. It shares no file with WO-029 and may run beside it.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/ui/fonts.ts` | NEW | Plus Jakarta Sans (UI) and JetBrains Mono (all numerals/data), loaded from `@fontsource` — self-hosted, so no third-party font request is made from a customer's own domain when BP-004 renders. Exports the two CSS variable names the root layout binds. |
| `src/ui/type.css` | NEW | The scale `BUILD.md` §2.3 fixes: headings Jakarta 700–800, letter-spacing −0.02em, `text-wrap: balance`; body 15px/1.55; uppercase 10.5–11px eyebrows. Plus one utility class, `.num`, that applies JetBrains Mono with `font-variant-numeric: tabular-nums` — the one mechanism the numeral rule is enforced through, so a component cannot half-apply it. |
| `tests/ui/fonts.test.ts` | NEW | The tests below. |

## Interfaces
Exposes:
```ts
// src/ui/fonts.ts
export const fontVariables: string   // the class the root layout puts on <html>
```
and `src/ui/type.css`'s `.num`.
Consumes: nothing.

## Steps
1. Add the two `@fontsource` imports and expose the variable names.
2. Write `type.css` from `BUILD.md` §2.3.
3. Write the tests; watch the "no third-party font request" test fail first by
   switching one family to a hosted CDN URL.
