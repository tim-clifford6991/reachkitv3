# WO-103 — The branded shell, its plain-text twin, and composeMail()

- Branch: wo/WO-103-mail-shell-compose
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-103.html
- Signed-off: (pending — design-guardian)

## Goal
Assemble one branded frame and one plain-text frame around a rendered block list
and return both bodies plus the omitted indexes from a single `composeMail()`
call.

## Provisional against an empty repo
**No `src/` exists.** All files NEW, inside BP-053's `src/lib/mail/shell/**`
glob (ADR-040 point 3: "the shell, the block model and its renderer, the register
itself, the send seam and the vendor call — is BP-053's").

**Placement choice (rule 1.1).** BP-053's `## Public interface` prints
`composeMail` under the comment header `// src/lib/mail/blocks/types.ts`. This WO
places it at `src/lib/mail/shell/compose.ts` instead. Derivation: ADR-040 point 3
names the shell as the thing that frames every mail, `composeMail` is the
shell-plus-blocks assembly, and a `types.ts` that exports a function is a file
whose name lies. Both paths are inside BP-053's own `code:` globs, so no owner
changes. Cost of reversing: one file move and one import edit; no behaviour, no
schema, no interface change. Flagged, not asked (rule 1.1).

Reuse check (rule 7.2): `registry/capabilities.md` gives `composeMail()` to
BP-053 and nothing else. No shell exists.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/mail/shell/frame.ts` | NEW | The branded HTML frame: header, body slot, footer, and the opt-out slot rendered when `optOut` is supplied. Uses BP-018's named tokens only; no hex literal, no inline font stack that is not a token. |
| `src/lib/mail/shell/text-frame.ts` | NEW | The plain-text twin of the same frame — same sections, same order, the opt-out rendered as a labelled URL. |
| `src/lib/mail/shell/compose.ts` | NEW | `composeMail()` verbatim from the blueprint's signature. Calls `renderBlocksHtml` and `renderBlocksText` (WO-101/WO-102) on one block list, wraps each in its frame, returns `{ html, text, omitted }`. Pure and synchronous — no I/O, no interpolation engine (BP-053 NFR budget: "under 5 ms for a mail of twenty blocks"). |
| `tests/mail/shell/compose.test.ts` | NEW | Both bodies returned, same blocks, `omitted` agrees with both renderers. |
| `tests/mail/shell/shell-tokens.test.ts` | NEW | The frame emits no colour or font literal that is not a BP-018 token name. |

**Test-directory note — the borrowed home is returned.** When this WO was cut,
BP-053's `code:` declared `tests/mail/send/**`, `tests/mail/blocks/**` and
`tests/mail/kinds/**` but no shell test glob, so rather than create a test
directory outside a declared glob this WO put the shell's tests in the send
directory and reported the gap. **`structure.md` gained rule 4a on 2026-08-31** —
"a node that globs a source directory globs its tests", closing what it calls "a
home, but the wrong one, and the sort of gap that reads as coverage" — and names
this as one of the two places it had happened: BP-053 gained `tests/mail/shell/**`
along with a vendor test glob, which is WO-105's to use, not this WO's. The two
files above now sit beside the `src/lib/mail/shell/**` they exercise. Nothing else
in the plan changes, and no other work order names either path.

## Interfaces
**Exposes** (verbatim from BP-053 `## Public interface`):
```ts
/** Every value that can be absent enters as a Measured<T>. A template holds no
 *  conditional and cannot format a number itself, so no template can forget
 *  criterion 1. */
export function composeMail(m: {
  kind: MailKind
  subject: CopyKey
  blocks: readonly MailBlock[]
  optOut?: { href: string }            // BP-029's lead mail; BP-059's toggle mail
  measurement?: MeasurementState       // required for 'weekly', rejected for every other kind
}): { html: string; text: string; omitted: readonly number[] }
```
**Consumes**: `MailBlock`, `renderBlocksHtml`, `renderBlocksText`,
`omittedIndexes` (WO-101, WO-102); `MailKind` (WO-104); `copy()` (BP-019);
`src/ui/theme.css` tokens (BP-018).

## Steps
1. Write both tests first and watch them fail.
2. `frame.ts` and `text-frame.ts`, section-for-section identical in structure.
3. `compose.ts`: assemble, return, no branching on kind.
4. Type the `measurement` parameter as accepted-and-ignored, with a `// HELD:
   WO for MeasurementState` comment naming REQ-064's third REVIEW line — the
   field is in the blueprint's signature and removing it would change a contract
   this WO does not own; its **behaviour** is the held WO's.
5. Mutation check: delete the text-frame call and confirm `compose.test.ts` fails.
