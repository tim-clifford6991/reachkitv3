# WO-270 — The repository's top-level set is asserted against structure.md rule 7 as amended — `.claude/` admitted

- Branch: wo/WO-270-top-level-set
- Estimate: ≤1 day (well under; one test file, one set and its comment)

## Goal
Bring `tests/app/toolchain.test.ts`'s top-level-directory assertion back into
agreement with `structure.md` rule 7 as amended on 2026-09-02, so that the
vendored `.claude/` directory committed under 61f1fd0 is admitted as a member of
the fixed set — not as never-committed tooling — and any *other* new top-level
directory still fails the test.

## Provenance and the fail-first observation
`tests/app/toolchain.test.ts` exists (WO-001, `status: done`) and is the one
place the top-level set is asserted; this order extends it and creates no
second assertion (rule 7.2). Its `allowed` set names the five directories rule
7 fixed before the amendment; its `toolingOnly` set names only directories that
are never committed (`node_modules`, `.next`, `coverage`, `.git`), which is the
wrong set for `.claude/` — that directory is committed and is a member of rule
7's set by the registry's own words.

**The test is already failing, and that is this order's fail-first
observation.** Run on `doctrine-0.11.0` on 2026-09-03:
`› "no top-level directory outside structure.md rule 7's set is present"` —
`expected [] received [".claude"]`, 1 failed / 10 passed. The implementer does
not need to construct a failing state before editing; the repository is in it.
After the edit, the discriminating check is the reverse: remove `.claude` from
`allowed` again and the same case must fail again with the same received value.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `tests/app/toolchain.test.ts` | MODIFY | In the case `"no top-level directory outside structure.md rule 7's set is present"`: add `.claude` to the `allowed` set (not to `toolingOnly` — it is committed, and rule 7 names it as a member of the set); replace the comment's quotation of rule 7 with the amended sentence quoted verbatim in `## Test plan` below, so the comment and the registry say the same thing. Nothing else in the file changes. |

No exported type is touched, so the type fan-out check (planner step 1b) has
nothing to enumerate; `npm run typecheck` (`tsc --noEmit`, derived in WO-001
from the absence of a `typeCheck` key in `factory.config.json`) is run once
after the edit as a matter of course.

## Interfaces
Consumes: `sdlc-factory/docs/registry/structure.md` rule 7 (the set), read by a
person and transcribed into the test — the test reads the filesystem, not the
registry. Exposes: nothing; this is a test.

## Steps
1. Observe the failing case as it stands (the fail-first observation above).
2. Add `.claude` to `allowed` and update the comment; the case passes and the
   file's other ten cases are unchanged.
3. Remove `.claude` from `allowed`, watch the case fail with
   `received [".claude"]`, restore it.
4. `npm test` and `npm run typecheck`.
