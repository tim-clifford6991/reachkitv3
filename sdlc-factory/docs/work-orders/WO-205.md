## Goal
Judge one site's week once, idempotently, from that week's measurement alone — and expose the week's standings to a surface and to the weekly mail without ever recomputing a verdict.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/opportunities/verdicts/judge.ts` | NEW | `judgeWeek({ siteId, week })` — reads BP-050's account for that week: `not_measured` writes **no rows at all** and every page's standing is `no_week`; a partial week judges each page whose recorded test `evaluateAcceptance` can decide from what that week did measure and leaves every other page `not_measured` with no row. For each judged page in the public population it composes the verdict (WO-204), the movement (WO-204) and `verifyFailedAt`, and inserts one row. Idempotent per `(site_id, week)` on WO-203's unique key: a re-run inserts nothing further and mints no second verdict. Once a `domain_changed` row exists for a page, every later week is `not_judgeable` for that page (ADR-071 point 5); the other three causes lift on their own terms with no intervention. |
| `src/lib/opportunities/verdicts/read.ts` | NEW | `readWeek({ siteId, week })` — one indexed read on `(site_id, week_start)`, scoped to that week alone, returning a `WeekStanding` per publication and recomputing no verdict. `weeklyDigest({ siteId, week })` returns the same standings plus `weekMeasuredAt` for BP-016's mail. Neither writes anything; a week with no rows returns `no_week` or `not_measured` standings from the account, never an earlier week's verdict. |
| `tests/opportunities/verdicts/judge.test.ts` | NEW | An unmeasured week writes zero rows and every page reads `no_week`; a partial week judges the decidable pages and leaves the rest `not_measured` with no row; a re-run of the same week inserts nothing; a page on a destination that does not serve publicly gets no standing at all; a page whose 24-hour verification failed carries `verifyFailedAt` beside a verdict that is unchanged by it; a page with a `domain_changed` row in an earlier week is `not_judgeable` in every later week; a page whose search returns to the tracked set is judged again from that week; two sites in different time zones judged in one run carry `week_start` values a day apart. |
| `tests/opportunities/verdicts/read.test.ts` | NEW | A read for a week with no rows never returns a neighbouring week's verdict; a page that received a verdict in week 1 and became unjudgeable in week 3 reads `lastJudgedWeek` as week 1; a page that never received one reads null; the digest carries `weekMeasuredAt` and the same standings the surface reads; a site whose access ended is judged for no new week while every verdict already recorded stays readable with the date it was taken. |

## Steps
1. Write both test files first and run them; both must fail on a missing module.
2. Implement `judge.ts`. It reads the scan for the named week and no other — a verdict is a fact about the week it was taken, and reading any other measurement is what REQ-063's first non-goal forbids.
3. Write `no_week` and `not_measured` as returned shapes only. ADR-071 point 2: they are represented by the absence of a row, so a transient miss cannot be written down as a permanent state, because there is nowhere to write it.
4. Return `no_week` per page for uniformity of type, and record in the module's header comment that it is a property of the week, not of the page — BP-019 and BP-016 must render it once per week, never once per page (ADR-071 point 3).
5. `verifyFailedAt` is set on the standing and never consulted when composing the verdict. Assert that in the test with two fixtures differing only in the verification failure.
6. Make idempotency the unique key, not a guard: run `judgeWeek` twice in the test and assert the row count.
7. Run the tests. Then mutate: write a row for `not_measured` and confirm the partial-week test fails; fall back to the latest verdict when the requested week has none, and confirm `… never returns a neighbouring week's verdict` fails.

**Discriminates (mutation check, constitution §8).**
- Falling back to the most recent verdict when the requested week has no row makes `… never returns a neighbouring week's verdict` fail — and is the change that would show a customer last week's verdict as this week's.
- Writing a row for `not_measured` makes the partial-week test fail, and in production would let one missed measurement retire a paying customer's page from judgement permanently while every screen still rendered correctly (ADR-071's cost-of-reversing).
- Letting `verifyFailedAt` downgrade or withhold a verdict makes the two-fixture verification test fail — c1 says it is shown beside a verdict and never in place of one.
- Judging in UTC weeks makes the two-time-zone test fail; BP-051 decision 3 is why the stored week is the site's own Monday.
