# WO-057 — `admitFreeScan` — the six-step order, the network key, and the fail-open limiter

- Branch: wo/WO-057-admission-check
- Estimate: ≤1 day

## Goal
Answer *may a free scan start* against the free path's bounds in BP-012's fixed
order, without side effects and without consuming an allowance, so that every
render of a report address can ask the question.

## Interfaces

Exposes (verbatim from BP-023 `## Public interface`, `src/lib/scan/admission.ts`):

```ts
/** Opaque, salted, non-reversible. REQ-003 counts by network; no raw address is
 *  stored or logged anywhere in the product. */
export type NetworkKey = string & { readonly __networkKey: unique symbol }
export function networkKeyOf(forwardedFor: string | null): NetworkKey

/** Verbatim BP-012's declared union — the refusal reasons and their fields are
 *  that node's contract and are not restated differently here. */
export type Admission =
  | { admit: true }
  | { refuse: 'hourly';       retryAfterSeconds: number }
  | { refuse: 'in_flight';    sameDomain: boolean; runningScanId?: string }
  | { refuse: 'daily';        retryAfterSeconds: number }
  | { refuse: 'switched_off' }
  | { refuse: 'cooldown';     retryAfterSeconds: number }
  | { refuse: 'removed' }

/** Idempotent and free of side effects: BP-022 calls it on every render of a
 *  report address, and a render must never consume an allowance. */
export function admitFreeScan(a: {
  domain: CanonicalDomain; network: NetworkKey
}): Promise<Admission>
```

The evaluation order is BP-012's and is reproduced here as the step list only —
its reasoning lives in BP-012's `## Decisions` (rule 2.4): **removed → cooldown →
switched off / daily ceiling → in-flight → hourly**, with what each step reads
and returns given by BP-023's `## Error & edge behavior` table.

## Steps
1. Write the failing suites first.
2. Implement `networkKeyOf`: first `x-forwarded-for` entry, trimmed; IPv6
   truncated to its /64 prefix before hashing; HMAC with `IP_HASH_SALT`. A null
   or unparseable header still yields a key — a stable one for "unknown" — and
   never throws.
3. Implement the six steps in order, each an early return:
   `removed` (a `domain_blocks` row for the canonical domain);
   `cooldown` (latest `failed` scan of this domain inside `FAILURE_COOLDOWN_H`,
   `retryAfterSeconds` = the remainder);
   `switched_off` (`env.KILL_SWITCH`, no time promised);
   `daily` (count over `DAILY_WINDOW_H` vs `FREE_BOUNDS.scansPerDay`,
   `retryAfterSeconds` = until the 200th-newest ages out);
   `in_flight` (`status = 'running'` for this network, with `sameDomain` and
   `runningScanId`);
   `hourly` (count for this network over `HOURLY_WINDOW_H` vs
   `FREE_BOUNDS.scansPerIpPerHour`, `retryAfterSeconds` = until the 5th-newest
   ages out).
4. Wrap steps 2 to 6 in the fail-open handler: any read error returns
   `{ admit: true }` and logs the failure as such. **The `removed` step is
   outside that handler** — a `domain_blocks` read that errors refuses.
5. Make every `retryAfterSeconds` an elapsed duration in seconds, never a clock
   time (REQ-003's third assumption, confirmed).
6. Emit the one structured log line BP-023's NFR budget specifies: decision, the
   step that produced it, the hashed network key, the domain. Never a raw
   address.
