# WO-021 — fetches — ledger, cache and raw store in one table

- Branch: wo/WO-021-fetches
- Estimate: ≤1 day

## Goal
Create the one row that is at once the spend ledger, the cache and the raw store,
with the unique key the cache read uses and the index the ledger read uses.

## Provenance of this file plan
**This repository holds no `supabase/`.** Both paths are NEW, anchored to
BP-007's `code:` glob `supabase/migrations/*_fetches*.sql`.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `supabase/migrations/00000000000004_fetches.sql` | NEW | `fetches` — `id, scan_id, source, cache_key, policy_version, cost_cents, payload jsonb, created_at`. `unique (source, cache_key, policy_version)` for the cache read; index on `scan_id` for the ledger read. RLS enabled with **no request-scoped read policy** — `fetches` carries cost and raw vendor payloads and is reachable only through `dbAdmin()`. |
| `tests/costs/fetches-schema.test.ts` | NEW | The tests below. `structure.md` rule 4 puts BP-007's tests under `tests/costs/**`. |

## Interfaces
Consumes: the policy conventions WO-010 applied.
Exposes: the schema `withCostContext()` (WO-022) writes and reads. No code
interface.

## Steps
1. Write the migration exactly to BP-007's data-model delta.
2. Add the unique and the index.
3. Enable RLS with no request-scoped policy.
4. Write the tests; watch the "no second table" test fail first by adding a
   `spend_ledger` fixture table.
