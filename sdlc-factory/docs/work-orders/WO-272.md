# WO-272 — users.notify and sites.timezone — the two component-level columns of BP-017's delta that no leaf sub-token claims, migrated and asserted

- Branch: wo/WO-272-account-component-columns
- Estimate: ≤1 day

## Goal
Add the two columns BP-017's `## Data model delta` names as its own and no leaf
migrates — `users.notify` and `sites.timezone` — under BP-017's topic globs,
each with one owner, so the orders that read them (WO-107, WO-211, WO-218) have
a column to read instead of a claim to rest on.

## Provenance of this file plan
**This repository holds no `supabase/` and no `tests/account/` on this branch**;
WO-267 is building the substrate in a sibling worktree. All three paths are NEW.
`supabase/migrations/*_users*.sql` and `*_sites*.sql` are BP-017's `code:` globs
and structure.md rule 3 makes `users` and `sites` BP-017's topics; every leaf
sub-token under them (`users_billing`, `users_provisioning`, `users_subscription`,
`users_identity`, `users_erasure`, `sites_provisioning`, `sites_hosting`,
`sites_erasure`) is claimed by a leaf order, and none of those claims either
column. `tests/account/**` is BP-017's; every leaf owns a sub-directory beneath
it, so a file at the root is the component's under structure.md rule 2.

BP-002's data-model index names the owner in so many words —
"| `users.notify jsonb` | REQ-075 | `users` · BP-017 (leaf: BP-059) |" and
"| `sites.timezone` | REQ-073 c3 | `sites` · BP-017 (leaf: BP-057) |" — and says
of that index "it is not a second declaration of the delta … where an entry and
its owning node disagree, the owning node is right". WO-267's baseline row lists
neither column. BP-059 decision 4 and BP-057's `## Data model delta` say the
baseline holds them; that is a reading of BP-002 that BP-002's own text refutes,
reported to the architect in this order's return and not relitigated here.

Of BP-017's `depends-on` — BP-002, BP-005, BP-006, BP-016 — this slice consumes
BP-002 alone (WO-267's `users` and `sites`); a `depends-on` edge to an order this
SQL never touches would be a fabricated edge, so none is written.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `supabase/migrations/<ts>_users_notify_column.sql` | NEW | `alter table users add column notify jsonb not null default '{}'::jsonb`, with `check (jsonb_typeof(notify) = 'object')`. The column only: its shape and meaning are BP-059's ("this node holds its shape and its meaning"). No foreign key, no cascade (ADR-051 point 2). |
| `supabase/migrations/<ts>_sites_timezone_column.sql` | NEW | `alter table sites add column timezone text null`. No default — REQ-073 criterion 1 forbids a zone the customer did not state; nullability derived in `rests-on` row 2. |
| `tests/account/columns.test.ts` | NEW | The schema assertions named in the test plan, against the applied migrations; no I/O beyond the scratch database. |

## Interfaces
Exposes (verbatim from BP-017 `## Data model delta`):

> `users` — as `BUILD.md` §10, plus `notify jsonb`, `pending_email`,
> `pending_email_token_hash`, `pending_email_sent_at`, `deleted_at`,
> `paid_through`, `vat_number`, `billing_country`.
> `sites` — as §10, plus `timezone`, `publishing_enabled`.

Of that list, this order ships exactly `notify jsonb` and `timezone`; every other
column is a leaf's under its sub-token (WO-116, WO-129, WO-135, WO-140).

Consumes: WO-267's baseline `users` and `sites` tables (BP-002).

## Steps
1. Write the two migrations, one topic token each, no sub-token.
2. Apply locally on top of WO-267's baseline and RLS files.
3. Write the test; watch the default row fail first by omitting `default '{}'`,
   and the object-check row fail first by omitting the `check`.

  order in the corpus does it today (reported in this order's return; it is
  BP-061's or BP-033's, not BP-017's component seam).
- Reading or writing `users.notify` — WO-107 (BP-059).
- Reading `sites.timezone` — WO-211 (BP-045), WO-218 and WO-219 (BP-057).

  sub-token orders WO-116, WO-129, WO-135, WO-140.
- Regenerating `src/lib/db/types.generated.ts` — BP-002's generated artefact;
  no sibling migration order claims it and this one follows that practice.

## Rollback

applied database; no order writes either column until WO-107 and WO-218 land,
and neither is on a read path WO-267's own tests exercise.
