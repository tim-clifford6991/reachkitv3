# WO-232 — When a check is due, and the two ways it never will be

- Branch: wo/WO-232-verify-disposition
- Estimate: ≤1 day

## Goal
Ship `dispositionFor` and `dueNow`: the five dispositions of a publication's 24-hour check, decided from the row and never from the destination kind.

## File plan

> verified to exist, because none can. Placement is anchored to

> `code:` globs, and is provisional against a repo with no code: if the

> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/verify/due.ts` | NEW | `VerifyDisposition`, `dispositionFor`, `dueNow`. `not_yet` carries `dueAt`, so the surface can state **when** the check will run in the 24 hours before it does. A publication with `unpublished_at` set before `verify_due_at` is `never: 'taken_down_first'` — **no fetch is made and the row is not deleted**, because deleting it would break BP-045's idempotency guard (ADR-080). `never: 'no_live_address'` is decided from `live_url is null`, **not** from `destination.kind`, so a WordPress draft is excluded and so is any future destination that delivers rather than serves, without a second rule being written. `dueNow` selects only rows with `verify is null`, oldest due first — a completed check is never re-run and there is no re-verification schedule. |
| `tests/publish/verify/due.test.ts` | NEW | Each of the five dispositions from its own fixture; `not_yet` carries a `dueAt` and never an outcome; a page taken down before its due moment is `taken_down_first` and no fetch is made; a null `live_url` is `no_live_address` whatever the kind, including a hypothetical third kind; `dueNow` never returns a row whose `verify` is non-null; a crashed mid-run left the row due (the job is idempotent by the null check). |

**Exposes** — copied exactly from BP-049's `## Public interface`:

```ts
// src/lib/publish/verify/due.ts
export type VerifyDisposition =
  | { kind: 'not_yet';     dueAt: Date }                       // REQ-062 c3, the 24 hours before
  | { kind: 'due' }
  | { kind: 'done';        result: VerifyResult }
  | { kind: 'never';       because: 'taken_down_first' }       // REQ-062 c4
  | { kind: 'never';       because: 'no_live_address' }        // REQ-062 non-goal (REQ-060)

export function dispositionFor(publicationId: string): Promise<VerifyDisposition>
export function dueNow(limit: number): Promise<string[]>       // publication ids, oldest due first
```

**Exclusion is decided by a null live address, not by destination kind** (BP-049
decision 2). REQ-062's non-goal excludes a WordPress draft *because it has no
live address*; `if (kind === 'wordpress')` is a rule that says the wrong thing
and would be wrong for the first destination that delivers without serving. The
two are coextensive today, which is exactly why the wrong version would pass
every test — write the stated rule.

## Steps
1. Create `verify/due.ts` with the block above verbatim.
2. Decide `no_live_address` from `live_url is null`. Do not read `destination.kind` anywhere in this file — assert its absence in test.
3. Decide `taken_down_first` from `unpublished_at < verify_due_at`. Make no fetch and delete no row.
4. Implement `dueNow` on the partial index `(verify_due_at) where verify is null`, oldest first.
5. Write the "a null live address is excluded whatever the kind" test with a third hypothetical kind and watch it fail against a kind check (constitution §8).

`tests/publish/verify/due.test.ts` › **"the publication row of a never-verified

published reads as stale data, and deleting it is the housekeeping that silently
re-arms the duplicate post REQ-056 criterion 5 forbids.
