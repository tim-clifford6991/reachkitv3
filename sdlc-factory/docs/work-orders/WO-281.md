# WO-281 — The bounded scan and its progress stream — two ceilings, one Ending, six named stages, and the wire they reach a visitor on

- Branch: wo/WO-281-progress-stream
- Estimate: ≤1 day

## Goal
Ship what a visitor watches while a free scan runs: two ceilings neither of which is ever exceeded to finish outstanding work, exactly one `Ending` however the scan ends, the six named stages that advance as work completes rather than on a clock, and the server-sent-events response that carries them and closes after the one ending.

> **Read `decisions/ADR-021.md` before writing a line of this WO.** It is a
> landmine: raising the cap to finish the last call, and computing a partial
> score from the factors that were measured, both read as kindnesses and both
> break a promise a customer can be shown.

## Consolidation (rule 2.6)
WO-063's goal — "Serve BP-023's stage stream as server-sent events and nothing
more — one thin adapter" — cannot be stated without WO-060's stream, and WO-060's
`## Out of scope` hands the transport to WO-063 by name. WO-060 consumes WO-059's
`Ending` in its own type, emits it as the terminal event, and WO-059's
`## Out of scope` hands "the stage stream that carries the ending to a visitor" to
WO-060. Three orders, one journey step: JN-001 step 3 from the ceiling that ends
the scan to the wire the visitor reads it on.

Exposes (verbatim from BP-023 `## Public interface`, `src/lib/scan/ceilings.ts`):

```ts
/** REQ-003's "bounded moment", made total. A free scan reaches exactly one. */
export type Ending =
  | { kind: 'report'; complete: true;  stoppedReason: 'complete' }
  | { kind: 'report'; complete: false; stoppedReason: 'time_ceiling' | 'spend_ceiling' }
  | { kind: 'no_report'; stoppedReason: 'failed' }

/** The deadline every stage and every multi-call step re-checks, exactly as
 *  BP-007's `capHit()` is re-checked between calls. */
export interface Bounds {
  expired(): boolean                 // now ≥ startedAt + TIMING.reportCeilingS
  remainingMs(): number
  capHit(): boolean                  // delegates to the CostContext, CAP_FREE
  stopNow(): 'time_ceiling' | 'spend_ceiling' | null
}
export function withFreeBounds<T>(
  a: { scanId: string; startedAt: Date },
  body: (b: Bounds) => Promise<T>
): Promise<{ result: T | null; ending: Ending }>
```

export type StageName =

## Steps

**WO-059's steps** (renumbered; order within the block unchanged):

1. Write the failing suites first, ADR-021's two prohibitions among them.
2. Implement `Bounds` over an injectable clock so the deadline tests need no real
   waiting; the clock is a parameter of the module, never read from a global
   inside the returned object's methods.
3. Implement `withFreeBounds`: run `body(bounds)`; when `stopNow()` fires,
   abandon outstanding work and return the `report` ending with the matching
   `stoppedReason`. Time is checked first when both fired in the same tick, since
   `TIMING.reportCeilingS` is the bound REQ-003 criterion 5 states absolutely.
4. Implement the `no_report / failed` ending per BP-023 decision 4: reached only
   when no ceiling was reached and every driver ended `unmeasured` with reason
   `undeterminable`. Any `not_attempted` anywhere means a ceiling acted, and a
   ceiling always yields a report.
5. Emit the one ending log line BP-023's NFR budget specifies: `stoppedReason`,
   elapsed ms, cents spent, whether the context degraded. Return none of it from
   `progress()` — no spend figure ever reaches a visitor.
6. Add the source assertions that no override exists.

**WO-060's steps** (renumbered; order within the block unchanged):

7. Write the failing suites first.
8. Declare `StageName` and freeze `STAGES` in order. Assert at module load that
   `STAGES.length === 6` and that every `StageName` member appears exactly once.
9. Implement `progress(scanId)` as an async iterable over the scan's recorded
   stage transitions, emitting entry and exit events per stage.
10. Add the heartbeat: if no event has been emitted for `TIMING.progressHeartbeatS`,
   emit `{ heartbeat: true }`. The heartbeat never advances a stage and never
   carries a stage name.
11. Emit exactly one `{ ending }` and then close the iterable. After the ending,
   the iterable is done — no further event of any kind.
12. On a stage the ceilings cut off, emit no `done: true` for it; the outputs are
   recorded `unmeasured / not_attempted` by the pipeline (WO-277's arm), never 0
   and never simply absent.
13. Emit the one structured log line per stage transition BP-023's NFR budget
   specifies.

**WO-063's steps** (renumbered; order within the block unchanged):

14. Write the failing suite first.
15. Implement the `GET` handler returning a streaming response with
   `text/event-stream`, `no-store` and `noindex`.
16. Serialise each `StageEvent` verbatim as the event payload — no renaming, no
   added field, no percentage.
17. Close the response after the single `ending` event and release the iterator.
18. Handle a disconnected client by cancelling the iterator: no background
   continuation for a visitor who closed the page (REQ-003's non-goal).
19. An unknown or malformed `scanId` responds 404 on this API route — the promise
   that a *report address* never 404s is REQ-001 criterion 5's and binds
   `/scan/{domain}`, not this transport path.
