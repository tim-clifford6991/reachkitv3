# WO-022 — The cost context — cache-first, ledger-always, cap-degrades

- Branch: wo/WO-022-cost-context
- Estimate: ≤1 day

## Goal
Run every vendor and model call inside a per-scan context that reads cache first,
ledgers what was spent whether or not the call succeeded, and returns a value at
the cap instead of throwing.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW, anchored to
`structure.md`'s row for `src/lib/costs/**` and BP-007's `code:` globs.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/costs/index.ts` | NEW | `withCostContext()` and the `CostContext` implementation, exactly BP-007's interface. Opens the context, runs the body, and at close writes the roll-up (`spentCents`, `degraded`) to `scans.cost_cents` and `scans.status`. |
| `src/lib/costs/cache.ts` | NEW | The cache read keyed `source + cacheKey + policyVersion` with the freshness window in days. **An empty payload is always a miss; there is no negative cache.** Nothing is ever deleted — a bumped `policyVersion` is how a changed derivation invalidates. |
| `src/lib/costs/ledger.ts` | NEW | `recordFetch`'s write half: a row is written for every call that reached the vendor, including one that succeeded at the vendor and failed on parse. |
| `tests/costs/context.test.ts` | NEW | The tests below. |

## Interfaces
Exposes (verbatim from BP-007 `## Public interface`):
```ts
export type CapName = 'FREE' | 'DEEP' | 'WEEKLY' | 'DRAFT'

export function withCostContext<T>(
  ctx: { scanId: string; cap: CapName; policyVersion: number },
  body: (cost: CostContext) => Promise<T>
): Promise<T>

export interface CostContext {
  /** Cache-first, ledger-always. `fresh` false means the payload came from cache
   *  and cost nothing. An empty payload is always a miss; there is no negative
   *  cache. */
  recordFetch<P>(call: {
    source: string           // vendor endpoint or model id
    cacheKey: string
    freshnessDays: number
    costCents: number
    run: () => Promise<P>
  }): Promise<{ payload: P; fresh: boolean; costCents: number } | { skipped: 'cap' }>

  capHit(): boolean          // re-checked between calls in any multi-call step
  spentCents(): number
  degraded(): boolean
}
```
Consumes: `db()`/`dbAdmin()` (BP-002), `CAPS` and `CACHE_WINDOWS_D` (BP-005).

## Steps
1. Write `cache.ts` and prove the no-negative-cache rule by test.
2. Write `ledger.ts` and prove the spend-then-fail case.
3. Write `index.ts` with the three-armed `recordFetch` return.
4. Write the tests; watch the cap case fail first by throwing a `CapExceeded`
   instead of returning `{ skipped: 'cap' }`.
