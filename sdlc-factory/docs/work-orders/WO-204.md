## Goal
Decide whether a recorded test can be evaluated from what a week measured, turn a decided test into one of the three verdicts in the right order, and carry a decline rather than smoothing it.

## Steps
1. Write the three test files first and run them; each must fail on a missing module.
2. Implement `evaluate.ts`. It reads the recorded `Acceptance` and never writes it — WO-181's trigger is the invariant, and this module holds no write path to `opportunities` at all (REQ-047 c8, REQ-063 c6).
3. Implement `verdict.ts` with the evaluation-then-age order. BP-051 decision 4: aging first would report a page that is demonstrably working as too early to judge, which is the opposite of the promise.
4. Implement `movement.ts`. `from` and `to` stay `Measured<number>`; nothing here rounds, averages or replaces a value.
5. Run the tests. Then mutate: age before evaluating and confirm the young-and-passing case fails; round the movement values to integers and confirm the decline case fails.

## Test plan
> Watch it fail first (constitution §8): every test below is written and
> run against the absent implementation before the implementation exists.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| **REQ-063 c2** Given a page published less than three weeks ago, when its verdict is produced, then it is marked as working if it already passes its recorded test, and otherwise as too early to judge rather than as not working. | `verdict.test.ts › a page published less than three weeks ago that already passes reads working` and `… otherwise too early, never not working` |
| **REQ-063 c3** Given a page whose measurement for its target search is worse this week than at the previous re-measurement, when its result is shown, then that decline is shown beside its verdict rather than hidden, rounded away or replaced by the better earlier figure. | `movement.test.ts › a worse measurement sets declined and carries both raw values` and `… the better earlier figure is never substituted` |
| **REQ-063 c4** Given the weekly re-measurement has completed, when the customer is notified, then they receive each page's verdict and what moved since the previous measurement, every figure carrying its change, the date it was measured, and — where the measurement it is compared against is not the previous week's — the interval that change spans. | `movement.test.ts › a gap in the series gives spansWeeks greater than one` — the notification that states it is WO-205's and BP-016's |
| **REQ-063 c6** Given a published page whose recorded acceptance test (REQ-047 criterion 8) can no longer be evaluated — its target search is no longer measured, the customer unpublished the page (REQ-056 criterion 7), the question it named left the tracked set when the market changed (REQ-071 criterion 7), or the customer changed the domain the site is measured under, so every measurement the test was written against is about a different website and the page receives no further working, too early or not working verdict (REQ-071 criterion 14) — when verdicts are produced, then it is marked as no longer judgeable, with one written line saying which of those happened and the date of the last verdict it did receive — or, where it never received one, that it was never judged; no working, too early or not working verdict is produced for it that week or afterwards while that holds; and its recorded test is not rewritten to something that could be judged. | `evaluate.test.ts › each of the four causes is returned distinctly` and `… the recorded test is not rewritten to something that could be judged` (the module has no write path) |

**Discriminates (mutation check, constitution §8).**
- Aging before evaluating makes the young-and-passing case read `too_early` — the test asserts `working`, and the mutation is the natural reading of "too early to judge".
- Collapsing two causes into one fails `each of the four causes is returned distinctly`; ADR-071 point 5 is why `domain_changed` in particular must not be merged with the three that lift.
- Rounding or smoothing a decline makes the c3 test fail; a test that only checked `declined` would survive a substituted `from` value, which is why both raw values are asserted.
