# WO-127 — requestMagicLink — three answers to one request, and no account-existence oracle

- Branch: wo/WO-127-request-magic-link
- Estimate: ≤1 day

## Goal
Answer a request for a sign-in link in exactly three ways — send it, say a
payment is held and the account is opening, or say there is no account — without
letting the difference between them reveal anything, and without ever consulting
whether access is still paid for.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` and BP-032's `code:` glob
> `src/lib/account/provisioning/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/provisioning/magic-link.ts` | NEW | Exports `requestMagicLink(email)` with BP-032's signature verbatim. Three branches over the lowercased address: an account exists → `issueLink({ purpose: 'sign_in' })` and `{ sent: true }`; no account but a completed Checkout Session is held against the address → `payment_held_account_opening` with `lineKey: 'signin.payment_held'` and **no further purchase offered**; neither → `no_account` with `lineKey: 'signin.no_account'`. **Imports nothing from `src/lib/account/billing/**`** — BP-032: "Never consults access: a customer past their paid-through date is sent a link and can sign in (REQ-076 c5, REQ-020 c4)." All three branches take the same rate limit and the same code path shape. |
| `tests/account/provisioning/magic-link.test.ts` | NEW | One case per branch; a lapsed customer (`paid_through` in the past) still gets `{ sent: true }`; a case-different address resolves to the same account; a source-level assertion that this module imports no billing symbol; and a timing/shape assertion — the three branches perform the same number of database round trips and return within the same measured band, so neither latency nor wording distinguishes them. |

## Interfaces
Consumes (verbatim from BP-061's `## Public interface`):
```ts
export function issueLink(a: { userId: string; to: string; purpose: LinkPurpose }):
  Promise<{ issued: true; expiresAt: Date } | { issued: false; reason: 'vendor' }>
```
Exposes (verbatim from BP-032's `## Public interface`):
```ts
export function requestMagicLink(email: string): Promise<
  | { sent: true }
  | { sent: false; answer: 'payment_held_account_opening'; lineKey: 'signin.payment_held' }
  | { sent: false; answer: 'no_account';                   lineKey: 'signin.no_account' }
>
```

## Steps
1. Write the three branch cases and watch them fail.
2. Implement `magic-link.ts`.
3. Add the lapsed-customer case — it is the one that fails if somebody ANDs the
   access gate into this function.
4. Add the import-absence and equal-shape assertions.
