# WO-269 — The layout law, declared and checked — Surface with its required arms, the conformance suite at five widths, its canary, and the browser runner

- Branch: wo/WO-269-layout-law
- Estimate: ≤1 day

## Goal
Create BP-018's `src/ui/layout/**` and `tests/ui/layout/**` so that a screen
root cannot compile without declaring its three band arms, every App Router
route is rendered in a real browser at five widths against ADR-093 decision 6's
four checks, and the one fixture that overflows on purpose is seen to fail —
with the browser driver and the script that run it landing in BP-001's root
toolchain (BP-001 decision 2).

## Interfaces

**Consumes:** `design/tokens.md` §2b by token name — `--breakpoint-lg`,
`--breakpoint-xl` (transcribed once into `BAND_MIN`, pinned against `:root` by
the sweep) and `--t-floor` (read from `:root` at run time, never transcribed);
`react` types; `playwright` (Chromium only) as the driver; WO-001's `npm run
typecheck`, `npm test`, `npm run build`. Nothing from `src/lib/**`.

**Exposes** (verbatim from BP-018 `## Public interface`, "Layout (ADR-093)"):
```ts
// ── Layout (ADR-093). Three bands, closed; a fourth is an ADR, not a query. ──
export const BANDS = ['compact', 'medium', 'wide'] as const
export type Band = (typeof BANDS)[number]

/** What this surface does in one band. No optional member: a surface that has
 *  nothing to say at a band says so with `same-as-below`, which is a decision
 *  someone made rather than a field someone forgot. */
export type Arm =
  | { kind: 'same-as-below' }
  | { kind: 'columns'; count: 1 | 2 | 3 }
  | { kind: 'declared'; note: string }

/** Every screen root is a `Surface`. `arms` is required and has no default, so
 *  a screen that declares no band behaviour fails to compile — not a test.
 *  `Surface` renders no chrome and is not a widget: BUILD.md §2.2's closed set
 *  of five custom components is untouched by it. */
export function Surface(p: {
  arms: Record<Band, Arm>
  children: React.ReactNode
}): JSX.Element
```
Plus `BAND_MIN` (this order's, see Parameters) and the script `npm run
test:layout` on BP-001's root toolchain.

## Parameters chosen (rule 1.1)
- **Driver: `playwright`, Chromium only.** Alternatives: `puppeteer` (same
  engine, no viewport-emulation advantage); Vitest browser mode
  (`@vitest/browser-playwright`) — rejected because it renders components, and
  the enumerator is the route tree, which needs the Next server. Reversal: one
  devDependency and `browser.ts`.
- **A fourth vitest project, not a second config file.** A root
  `vitest.layout.config.ts` would be a file `structure.md`'s root-config row
  does not name. Reversal: one project block and one script line.
- **`npm test` excludes `layout`.** A browser binary is not installed by `npm
  install`, and every sibling work order's stop condition is `npm test`
  green. Reversal: one script line.
- **`BAND_MIN` lives in `src/ui/layout/`, not `constants.ts`.** `structure.md`
  rule 5 pins `BUILD.md`'s numbers into BP-005's file; a design token's code
  home is BP-018's (`structure.md` top-level row), and WO-006 is in flight on
  `constants.ts`. The sweep's token pin is what keeps the transcription and
  the CSS declaration from diverging (the `tests/pins.test.ts` shape).
- **Viewport height 480 at every width.** `browser.ts` opens each of the five widths at `{ width, height: 480 }`; the height is one named constant beside `BAND_MIN` with its provenance in a comment (ADR-093 decision 6, amended 2026-09-03; the promise is REQ-099 criterion 1) and no other literal. Reversal: one suite parameter.
- **The canary is a static fixture under `tests/ui/layout/fixtures/`, navigated
  by `file://`.** A page under `src/app/` would be enumerated by the sweep it
  is meant to fail, would ship unless gated, and would sit in BP-001's glob
  rather than BP-018's. Same browser, same four functions. Reversal: one file
  moved and one enumerator exclusion.
- **`Surface` applies no style.** An `Arm` of kind `columns` is a declaration
  the screen's own CSS honours; a primitive that laid out a grid would carry
  spacing of its own and reopen `BUILD.md` §2.2's closed set. Reversal: one
  component body.
- **Type fan-out check (1b), run 2026-09-02** on a scratch copy of `bands.ts`
  and `Surface.tsx`: `npm run typecheck` reports one error, in the new file
  itself — `TS2503: Cannot find namespace 'JSX'` under `@types/react` 19.2 —
  and zero with `React.JSX.Element`. No existing file consumes the new type,
  so the plan has no type-change rows; the return type is spelled
  `React.JSX.Element` (an internal name, rule 1.1).

## Steps
1. Write `fixtures/canary.html` and `canary.test.ts`. Run the file once under
   the existing jsdom `ui` project and record that checks 1–4 **pass** on the
   canary there — the vacuous run rests-on row 1 describes, watched before the
   cure exists (constitution §8).
2. Add `playwright`, the `layout` project and the two scripts; write
   `browser.ts`. Run `npm run test:layout` with no Chromium installed and
   record the written refusal; install Chromium; watch `canary.test.ts` go
   green because the fixture now fails all four checks.
3. Write `surface.test.tsx` and watch it fail (no module); create `bands.ts`,
   `Surface.tsx`, `index.ts`; `npm run typecheck` and `npm test` green.
4. Write `routes.test.ts`, then `routes.ts` and `widths.ts`.
5. Write `layout.test.ts` over `checks.ts`; run the sweep and record its
   coverage line (`0 routes × 5 widths` today).
6. Write `tests/app/layout-runner.test.ts`; `npm test`, `npm run test:layout`,
   `npm run typecheck`, `npm run lint`, `npm run build` all green.
