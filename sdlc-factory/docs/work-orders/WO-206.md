# WO-206 — The publishing type leaf — State, Actor, DraftView, Publication, DestinationAdapter, DeliveryResult

- Branch: wo/WO-206-publish-types-leaf
- Estimate: ≤1 day

## Goal
Create `src/lib/publish/types.ts`, the leaf type module that lets BP-046, BP-048, BP-049 and BP-058 name the publishing contracts without importing anything from `src/lib/publish/`.

**Exposes** — copied exactly from BP-045's `## Public interface`:

```ts
// src/lib/publish/types.ts — the leaf; imports nothing from src/lib/publish/
export type State =
  | 'planned' | 'generating' | 'in_review' | 'approved' | 'publishing'
  | 'published' | 'skipped' | 'failed' | 'needs_attention' | 'unpublished'

export type Actor =
  | { kind: 'customer'; userId: string }
  | { kind: 'system'; job: 'draft/generate' | 'publish/execute' | 'publish/verify' }

/** Declared **here**, in the leaf, not in `attempt/`. `DeliveryResult.reason`
 *  names it and `types.ts` imports nothing from `src/lib/publish/`, so declaring
 *  it under `attempt/index.ts` made this file uncompilable as specified.
 *  `attempt/index.ts` re-exports it, which is why every caller's spelling is
 *  unchanged. `RETRYABLE` stays in `attempt/` — it is policy, not shape. */
export type FailureReason =
  // repeated attempt could clear it — retried, at most three times (REQ-056 c4)
  | 'network' | 'timeout' | 'destination_unavailable' | 'rate_limited'
  // repeated attempt could not clear it — straight to needs_attention
  | 'credentials_expired' | 'credentials_invalid' | 'dns_not_pointed'
  | 'destination_rejected' | 'no_destination'

export interface DeliveryResult {
  ok: boolean
  /** Set only where the destination serves the page publicly (REQ-056 c6). */
  liveUrl?: string
  /** Opaque to us; the post/page id at the destination. Never rendered. */
  remoteId?: string
  /** Did *this call* make the page live at the destination? ADR-081's
   *  discriminator, declared by the adapter that did or did not do it and
   *  stored by `publish()` as `publications.made_live_by_us`. `true` for the
   *  hosted adapter, `false` for WordPress, which delivers a draft. Not
   *  `servesPublicly` and not `liveUrl != null`: the first is a property of the
   *  destination rather than of what we did to this page, and the second is
   *  null for every WordPress row by design. */
  madeLive: boolean
  reason?: FailureReason
}

/** ADR-081. Three outcomes, never a boolean: a boolean cannot separate "the
 *  post ReachKit made live is a draft again" from "the post ReachKit never made
 *  live was named and not touched", and those are two different promises to the
 *  customer about their own site. */
export type UnpublishResult =
  | { ok: true;  outcome: 'removed' }             // hosted — REQ-056 c15, 410 at BP-047
  | { ok: true;  outcome: 'returned_to_draft' }   // WordPress, made live by us — REQ-079 c4
  | { ok: true;  outcome: 'named_for_removal' }   // WordPress, never made live — REQ-056 c16
  | { ok: false; reason: FailureReason }

export interface DestinationAdapter {
  kind: 'hosted' | 'wordpress'
  /** Does this destination serve the page publicly at an address we can
   *  measure? `true` for hosted, `false` for WordPress. It is the population
   *  boundary for REQ-063 c1's weekly verdicts and for the 24-hour
   *  verification. A field on the adapter, not a `kind === 'hosted'` test at
   *  each caller, so a third adapter cannot join the judged population by
   *  defaulting into it (BP-015 decision 3; BP-051's second `rests-on`). */
  servesPublicly: boolean
  /**
   * MUST be idempotent on `idempotencyKey` (the draft id): a second call with
   * the same key after a delivery whose outcome we never recorded must find
   * the existing post and return it, never create a second one. The unique
   * index cannot reach inside a destination we do not own — ADR-080.
   */
  deliver(page: RenderedPage, cfg: DestinationConfig, idempotencyKey: string): Promise<DeliveryResult>
  /** Which arm is taken is read from `publications.made_live_by_us`, never from
   *  a re-read of the destination — ADR-081. */
  unpublish(pub: Publication, cfg: DestinationConfig): Promise<UnpublishResult>
  health(cfg: DestinationConfig): Promise<DestinationHealth>
}
```

Three things in the block above were this work order's own additions when it was
first cut, reported upward rather than made silently. **All three are now BP-045's
own text and are copied, not chosen** (2026-08-31): `servesPublicly` on
`DestinationAdapter`, `FailureReason` declared in the leaf with `attempt/index.ts`
re-exporting it (`RETRYABLE` stays in `attempt/` — it is policy, not shape), and
`madeLive` on `DeliveryResult` with `UnpublishResult` as a closed union, both from
ADR-081. Nothing here is a planner parameter any longer; if the block above and
BP-045's `## Public interface` ever disagree, BP-045 wins and this work order is
wrong.

**`madeLive` is required, and that is the point.** An optional `madeLive?:
boolean` would let a future adapter omit it and be read as "never made live",
which silently routes every one of its pages into REQ-056 c16's population —
"named for the customer, not touched" — for a destination ReachKit may well have
made live. ADR-081's whole mechanism is that the adapter *states* what it did.
Making the member optional is the mutation `types.test.ts` catches.

## Steps
1. Create `src/lib/publish/types.ts` with the block above, verbatim, plus the two additions the interface note records.
2. Declare `FailureReason` as the nine-member union BP-045 states under `attempt/index.ts`: `network`, `timeout`, `destination_unavailable`, `rate_limited`, `credentials_expired`, `credentials_invalid`, `dns_not_pointed`, `destination_rejected`, `no_destination`.
3. Declare `DraftView` with the ten fields BP-046 names: `id`, `siteId`, `state`, `vetoDeadline`, `approvedAt`, `approvedBy`, `hasUnsavedEdit`, `claimRecheckOutstanding`, `told`, and the `GoverningPair` in force at the moment of evaluation.
4. Declare `Publication` over the `publications` row WO-208 creates: `id`, `draftId`, `destinationId`, `siteId`, `deliveryState`, `attemptNo`, `claimedAt`, `publishedAt`, `unpublishedAt`, `liveUrl`, `remoteId`, `failureReason`, `mode`, and **`madeLiveByUs: boolean`** — the `made_live_by_us` column (WO-208), required and not optional for the same reason `DeliveryResult.madeLive` is. It is on `Publication` because `DestinationAdapter.unpublish` is handed a `Publication` and reads the arm from it (BP-045: "Which arm is taken is read from `publications.made_live_by_us`, never from a re-read of the destination"); an adapter that cannot see the column would have to re-read the customer's site, which is ADR-081 alternative 5, rejected.
5. Declare `DestinationHealth` as `'ok' | 'expired' | 'error'` (BP-058's, `BUILD.md` §10's enum unchanged), `DestinationConfig` as an opaque `unknown`-shaped record the adapter narrows, and `RenderedPage` as the title/slug/body/meta the adapter delivers. `UnpublishResult` is the four-arm union above, copied verbatim — **not** the `{ ok: true; removedFromDestination: boolean }` boolean this work order carried before ADR-081.
6. Write `tests/publish/machine/types.test.ts` and watch the shape assertions fail before `types.ts` exists (constitution §8).
7. Read ADR-081's warning block before touching the `UnpublishResult` union. `returned_to_draft` is an arm with **no members in production today**: REQ-060 c1 promises a WordPress post is never made live by us and BP-048 has no path setting any status but draft, so `made_live_by_us` is false on every WordPress publication this product can create, and every WordPress unpublish takes `named_for_removal`. Deleting the arm compiles, ships, and leaves the whole suite green except the exhaustiveness test this work order writes — which is why that test exists and why the arm is not a comment.
