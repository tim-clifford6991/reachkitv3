# WO-268 — The fifteen registered components — Btn, Card, Badge, Alert, Stat, Tabs, Table, Progress, Toggle, Steps, Join, Collapse, Input, Divider, Kbd — and the closed barrel

- Branch: wo/WO-268-registered-components

- Signed-off: 2026-09-03

> `design/previews/WO-031.html` is the sheet the design-guardian drew for the
> first eight of these components. It stands as the preview of record for
> this order until the guardian re-points or extends it; the planner does not
> write `design/`.

## Goal
Ship BP-018's registered daisyUI component set, all fifteen, each with no
default string and every label a required prop, exported from one closed
barrel so an unregistered widget has nowhere to be exported from.

## Why one order (rule 2.6)
WO-031 ("part 1") and WO-032 ("part 2") cut one capability — the registered
set — along a file: both wrote `src/ui/components/index.ts`, WO-032's stop
condition ("the set is closed at fifteen") could only be stated by naming
WO-031's eight, and WO-031's barrel existed for WO-032 to append to. That is
the merge test. Criteria and file plans below are carried verbatim, none
dropped.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW under BP-018's `code:`
glob `src/ui/**`.

## Interfaces
Exposes (verbatim from BP-018 `## Public interface`, the members this work order
ships):
```ts
// Registered components only — daisyUI primitives plus the five allowed customs.
export { Btn, Card, Badge, Alert, Stat, Tabs, Table, Progress, Toggle, Steps,
         Join, Collapse, Input, Divider, Kbd } from './components'
export type Tone = 'ok' | 'warn' | 'bad' | 'neutral' | 'accent'
// Series colours are `chart-you` and `chart-rival` only; Tone is for state and
// is never used for a series.
```
Consumes: `src/ui/theme.css` (WO-029), `src/ui/type.css` and `.num` (WO-030).

## Steps
1. Write `types.ts` with `Tone`.
2. Write the fifteen components, each with required label props and no default
   string.
3. Write the barrel with exactly the fifteen exports.
4. Write the two test files; watch the "no component has a default string" test
   fail first by giving `Alert` a fallback message, and the "closed at fifteen"
   test fail first by exporting a sixteenth.
