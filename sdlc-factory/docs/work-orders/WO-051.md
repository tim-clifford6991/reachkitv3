# WO-051 — The one canonical domain parser — `parseDomain`, `CanonicalDomain`, `DomainProblem`

- Branch: wo/WO-051-canonical-domain
- Estimate: ≤1 day

## Goal
Ship the product's single domain parser and its branded key, so that every
written form of one domain becomes one value and every malformed value becomes a
named handle, in the module ADR-020 fixes.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`,
> no `package.json` and no `tsconfig.json`. Placement follows
> `sdlc-factory/docs/registry/structure.md` (`src/lib/scan/**` is BP-012's
> container; BP-023 anchors `src/lib/scan/domain.ts` by the narrower glob) and is
> provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/scan/domain.ts` | NEW | The whole public interface below: the branded `CanonicalDomain`, the `DomainProblem` handles, `DomainParse`, and `parseDomain`. Canonicalisation is ADR-020 decision 1, in this order: lowercase; strip scheme; strip userinfo, port, path, query and fragment; strip a leading `www.`; strip a trailing dot; convert internationalised labels to punycode A-labels. Rejections are ADR-020 decision 2's five handles and no others. No DNS call, no fetch, no clock (ADR-020 decision 3). The public-suffix data is loaded once at module scope and held in memory. |
| `tests/scan/free/domain.test.ts` | NEW | The fixture suite named in the test plan. Table-driven: one row per written form, one row per rejection, plus the idempotence and injectivity properties. |

## Interfaces

Consumes: nothing inside this repository. One external data set — a public
suffix list — per this WO's first `rests-on` row.

Exposes (verbatim from BP-023 `## Public interface`, `src/lib/scan/domain.ts`):

```ts
// ── src/lib/scan/domain.ts — ADR-020 ───────────────────────────────────────
/** The product's one domain key. Produced only by `parseDomain`; every
 *  domain-keyed row, URL segment, cache key and counter uses this value. */
export type CanonicalDomain = string & { readonly __canonicalDomain: unique symbol }

export type DomainProblem =
  | 'empty' | 'not_a_hostname' | 'ip_literal' | 'no_public_suffix' | 'too_long'

export type DomainParse =
  | { ok: true;  domain: CanonicalDomain }
  | { ok: false; problem: DomainProblem }

/** Accepts every written form REQ-001 criterion 2 names — scheme or none, `www`
 *  or none, trailing path, any letter case, trailing dot, IDN — and returns one
 *  value for all of them. Does not resolve DNS and does not fetch. */
export function parseDomain(raw: string): DomainParse
```

## Steps
1. Add the public-suffix data source to the build and load it at module scope;
   assert at load that it is non-empty.
2. Write the failing fixture suite first (constitution §8, "watch it fail
   first"): every row of the test plan below, against a `parseDomain` that does
   not yet exist.
3. Implement the canonicalisation in ADR-020 decision 1's order.
4. Implement the five rejections. `too_long` is the label-length / total-length
   bound the hostname grammar fixes; `not_a_hostname` is anything that is not a
   sequence of hostname labels after canonicalisation.
5. Brand the success value. `CanonicalDomain` has exactly one producer — export
   no cast helper, no `asCanonicalDomain`, and no constructor beside
   `parseDomain`.
6. Run the suite; confirm every test that passed before step 3 existed is now
   failing for the right reason and passing after.

## Test plan

> Criteria are copied verbatim from `requirements/REQ-001.md`; line breaks are
> normalised to fit the table and no word is changed.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| REQ-001 c2 — "Given a visitor who enters a domain in any of its written forms — with or without a scheme, with or without `www`, with a trailing path, in any letter case — when they submit, then they arrive at the single public report address for that domain; no two of those forms produce different addresses or different stored reports." | `domain/parse · one domain, every written form, one key` — a table of at least these forms of one domain: `example.com`, `EXAMPLE.COM`, `www.example.com`, `http://example.com`, `https://WWW.Example.com/pricing?a=1#x`, `example.com.`, `example.com:8443` — asserts all parse `ok` and all yield the identical `CanonicalDomain` string. The address-level half of this criterion is WO-061's `canonicalRedirect` test; the key-level half is here. |
| REQ-001 c3 — "Given a visitor who submits a value that is not a well-formed public domain name — an empty value, an IP literal, or a hostname with no public suffix — when they submit, then one written line names what is wrong with the value and the visitor stays on the landing page with their input intact. A well-formed domain is accepted here whether or not it resolves; a domain that cannot be reached is a failed scan (REQ-003), not a rejected input." | `domain/parse · the three named rejections carry their own handle` — `''` and `'   '` → `empty`; `192.0.2.1`, `[2001:db8::1]`, `http://192.0.2.1/` → `ip_literal`; `localhost`, `myserver`, `example.invalidtld` → `no_public_suffix`. And `domain/parse · a well-formed domain that cannot resolve is accepted` — a domain in a real public suffix that resolves nowhere parses `ok`, and the test asserts by spy that no DNS or network API was called during the parse. The written line itself is BP-019's and is WO-070's / WO-069's to render. |
| REQ-001 c4 — "Given a report address whose domain segment is not a well-formed public domain name, when it is opened, then one written line names what is wrong with it and the visitor is offered the landing field — never a blank page, an unhandled error, or a scan." | `domain/parse · never throws` — a property test over adversarial inputs (empty, 10 000 characters, control characters, lone surrogates, `../`, `%00`, a full URL with credentials) asserting `parseDomain` returns a `DomainParse` for every one of them and throws for none. The rendering half of c4 is WO-069's. |
| REQ-001 c2, injectivity half | `domain/parse · distinct domains never collide` — `example.com`, `www2.example.com`, `example.co.uk`, `xn--e1afmkfd.xn--p1ai` and the unicode form of the last parse to four distinct keys, and the unicode and punycode forms of the same IDN parse to one. |
| REQ-001 c2, stability half | `domain/parse · canonical form is a fixed point` — for every `ok` result, `parseDomain(result.domain)` returns the same value. A parser that is not idempotent produces two keys for one domain on the second hop. |
