# WO-003 — Default-deny middleware and the one public allow-list

- Branch: wo/WO-003-middleware
- Estimate: ≤1 day

## Goal
Make authorisation default-deny at the edge of the web container, with one
declared allow-list of public paths, so a route added under `src/app/(account)/`
cannot become reachable by omission.

## Provenance of this file plan
**This repository holds no `src/`.** Both paths are NEW, anchored to BP-001's
`code:` glob `src/middleware.ts`.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/middleware.ts` | NEW | One matcher over every request. Denies by default; permits only a path matching the exported `PUBLIC_PATHS` allow-list, `/api/jobs/*`, `/api/stripe/webhook`, and Next.js internals. A denied request is redirected to the sign-in address prompt and the response body states nothing about whether an account or a payment exists. Reads no database: the session presence check is a cookie/JWT check only. |
| `tests/app/middleware.test.ts` | NEW | The discriminating tests below. |

## Interfaces
Exposes:
```ts
// src/middleware.ts
export const PUBLIC_PATHS: readonly string[]   // the one allow-list
export const config: { matcher: string[] }
export function middleware(req: NextRequest): NextResponse
```
Consumes: nothing outside Next.js. Session *identity* is BP-061's
(`currentSession()`); this middleware asserts only presence, so the account
container is not reachable before that node ships.

## Steps
1. Write `PUBLIC_PATHS` from BP-001's public route list, one entry per route.
2. Write the matcher and the deny branch.
3. Write the tests; add a new `(account)` route fixture and watch the
   "new account route is denied by default" test fail before the middleware
   exists (constitution §8).
