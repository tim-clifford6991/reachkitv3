# WO-235 — The published message — the live address and all four outcomes, sent whether they passed or failed

- Branch: wo/WO-235-published-telling
- Estimate: ≤1 day

## Goal
Ship `tellingFor()`: the occasion and payload for the `published` message, carrying the live address, all four outcomes and the list of those that failed — with a failed check never a reason to send nothing.

> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the
> implementer finds a file already present at one of these paths, they stop and
> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/verify/telling.ts` | NEW | `PublishedTelling`, `tellingFor(publicationId)`. Returns the live address, all four outcomes and `failed: readonly CheckId[]` — **possibly empty; never a reason not to send**. Carries the copy key `mail.published.verified` and no sentence. This module sends nothing: BP-016 sends it, on the same occasion either way, and the outcome of the checks never enters the decision whether to send. |
| `tests/publish/verify/telling.test.ts` | NEW | The telling is produced identically whether `failed` is empty or holds all four; `failed` names exactly the checks whose `Measured` value is a measured false, and never an `unmeasured` one; the payload carries the live address and a copy key and contains no sentence; the outcome of the checks does not appear anywhere in the send/no-send decision (a module-graph assertion that this module's result is not read by any suppression path). |

**Exposes** — copied exactly from BP-049's `## Public interface`:

```ts
// src/lib/publish/verify/telling.ts
export interface PublishedTelling {
  publicationId: string
  liveUrl: string
  result: VerifyResult
  failed: readonly CheckId[]        // possibly empty; never a reason not to send
  copy: 'mail.published.verified'
}
export function tellingFor(publicationId: string): Promise<PublishedTelling>
```

## Steps
1. Create `verify/telling.ts` with the block above verbatim.
2. Compute `failed` as the checks whose value is a measured `false`. An `unmeasured` check is not a failure — it was not observed.
3. Return the same shape whether `failed` is empty or full. Add no branch that suppresses on failure.
4. Write the "the message is sent on the same occasion whether every check passed or any failed" test first and watch it fail against an implementation that returns nothing when a check failed (constitution §8).
