# WO-142 — confirmDangerAction — unpublish everything, and publishing stays off

- Branch: wo/WO-142-unpublish-everything
- Estimate: ≤1 day

## Goal
Take every live page down through its destination's own adapter, report the ones
whose destination could not be reached, switch publishing off and leave it off —
and refuse the whole thing without a ticket, a taken export and a typed
confirmation.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` and BP-063's `code:` glob
> `src/lib/account/lifecycle/**`. Provisional against a repo with no code.
>
> **Scope note (ADR-081, ruled 2026-08-31).** BP-063's
> `blocked-by: [REQ-056, BP-015]` is **discharged**. The owner ruled **scope by
> liveness**, and BP-063 records what that changes here: "criterion 4's WordPress

| `src/lib/account/lifecycle/confirm.ts` | NEW | Exports `confirmDangerAction` with BP-063's signature verbatim, and the ticket guard both actions share: refuses unless the ticket exists, is unspent, is unexpired, and carries `takenAt` — the four refusal reasons are `no_ticket`, `export_not_taken`, `expired`, `spent`, plus `not_confirmed` for a mismatched typed confirmation. There is **no other entry point to either action**. This work order implements the `unpublish_all` arm; WO-143 adds the `delete_account` arm to this same file, which is why the two are sequential rather than parallel. |
| `src/lib/account/lifecycle/unpublish-all.ts` | NEW | Exports `UnpublishAllResult` verbatim and the take-down loop. For each live publication, calls BP-045's `DestinationAdapter.unpublish(pub, cfg)` and routes its `UnpublishResult` (ADR-081) through one `switch` with **no `default` arm**, closed by `const _never: never = outcome`. `removed`, `returned_to_draft` and `named_for_removal` each count once toward `takenDown`; only `{ ok: false }` puts that publication's destination into `stillLive`. **Chosen (rule 1.1):** all three `ok: true` arms count as taken down, derived from BP-063's own sentence — `stillLive` means "a destination that could not be reached, and not a page that was named rather than written to" — so a named page is not still-live, and `takenDown` is the only other counter `UnpublishAllResult` has. Reversing that is one line here and one test row. A destination that cannot be reached is **reported, never retried into silence** — its pages are collected into `stillLive` with `lineKey: 'danger.some_still_live'`, and `'danger.all_taken_down'` where none remain. Unpublishing is idempotent per publication, so a partial run followed by a retry converges. Then sets `sites.publishing_enabled = false` — and this module contains **no** write of `true` to that column, asserted by a source-level test (decision 2). Returns within 30 s or returns with `stillLive` populated for the destinations it could not reach in that window; it never blocks the customer on a dead destination. |
| `tests/account/lifecycle/confirm-guard.test.ts` | NEW | Each of the five refusal reasons, each leaving the account and its pages untouched; a `GET`-shaped call path does not exist (the function requires a ticket a customer's own action created); a ticket whose export was never taken refuses with `export_not_taken`. |
| `tests/account/lifecycle/unpublish-all.test.ts` | NEW | Every live publication on a **hosted** destination stops being served afterwards (asserted through BP-060's `hostedServingState`, not through a page fetch); a destination stubbed unreachable leaves its pages in `stillLive` with the `danger.some_still_live` key and the run still completes; a second run converges and takes nothing down twice; `publishing_enabled` is false afterwards and `publishingSwitchedOff` is `true`; the account stays active, its content stays listed and `contentSummary` is unchanged; the 30-second bound holds with a slow destination stub. |
| `tests/account/lifecycle/unpublish-outcomes.test.ts` | NEW | **ADR-081's empty arm, pinned so its removal fails rather than passes quietly.** `returned_to_draft` has no members in production today: REQ-060 c1 promises "a WordPress post is never made live by us" and BP-048 has no code path that sets any status but draft, so `made_live_by_us` is `false` on every WordPress publication this product can create and every WordPress unpublish takes `named_for_removal`. Three assertions. (a) **Type-level:** this file re-declares the same total match over `UnpublishResult` that `unpublish-all.ts` performs, ending in `const _never: never = outcome` — deleting an arm from the union, or dropping its case from the loop, is a type error rather than a green suite. (b) **Behavioural, from a fixture, not from production data:** an adapter stub returning `{ ok: true, outcome: 'returned_to_draft' }` is counted in `takenDown`, appears in **neither** `stillLive` nor the `danger.some_still_live` line, and produces no write from this module. (c) The same for `named_for_removal`, which is the arm every WordPress row actually takes today. The failure message names ADR-081 and REQ-079 c4 and states that the arm is unreachable, not dead — it is the branch REQ-079 c4 promises, held open against the day the product can publish into a customer's WordPress live. What the adapter does *inside* WordPress is asserted by BP-048's own discriminating test, not here. |
| `tests/account/lifecycle/publishing-stays-off.test.ts` | NEW | Decision 2 made enforceable: a source-level assertion that no file under `src/lib/account/lifecycle/**` writes `publishing_enabled = true`, and that `src/lib/publish/**` and `src/jobs/**` contain no write of `true` to it either — only the customer's own Settings toggle (BP-055/BP-057) does. The failure message names REQ-079 c5 and REQ-074 c3. |

## Interfaces
Exposes (verbatim from BP-063's `## Public interface`):
```ts
export function confirmDangerAction(a: { ticket: string; typedConfirmation: string }): Promise<
  | { ok: true; result: UnpublishAllResult }                       // unpublish_all
  | { ok: true; result: DeleteAccountResult }                      // delete_account
  | { ok: false; reason: 'no_ticket' | 'export_not_taken' | 'expired' | 'spent' | 'not_confirmed' }
>

export interface UnpublishAllResult {
  takenDown: number
  stillLive: ReadonlyArray<{ destinationId: string; kind: 'hosted' | 'wordpress'; liveUrls: readonly string[] }>
  publishingSwitchedOff: true          // c5 — and it stays off until the customer switches it on
  lineKey: 'danger.some_still_live' | 'danger.all_taken_down'
}
```
Consumes (verbatim from BP-045's `## Public interface`):
```ts
/** ADR-081. Three outcomes, never a boolean: a boolean cannot separate "the
 *  post ReachKit made live is a draft again" from "the post ReachKit never made
 *  live was named and not touched", and those are two different promises to the
 *  customer about their own site. */
export type UnpublishResult =
  | { ok: true;  outcome: 'removed' }             // hosted — REQ-056 c15, 410 at BP-047
  | { ok: true;  outcome: 'returned_to_draft' }   // WordPress, made live by us — REQ-079 c4
  | { ok: true;  outcome: 'named_for_removal' }   // WordPress, never made live — REQ-056 c16
  | { ok: false; reason: FailureReason }
```
Consumes (verbatim from BP-045's `## Public interface`, `src/lib/publish/types.ts`):
```ts
export interface DestinationAdapter {
  kind: 'hosted' | 'wordpress'
  /** Does this destination serve the page publicly at an address we can
   *  measure? `true` for hosted, `false` for WordPress. It is the population
   *  boundary for REQ-063 c1's weekly verdicts and for the 24-hour
   *  verification. A field on the adapter, not a `kind === 'hosted'` test at
   *  each caller, so a third adapter cannot join the judged population by
   *  defaulting into it (BP-015 decision 3; BP-051's second `rests-on`). */
  servesPublicly: boolean
  /**
   * MUST be idempotent on `idempotencyKey` (the draft id): a second call with
   * the same key after a delivery whose outcome we never recorded must find
   * the existing post and return it, never create a second one. The unique
   * index cannot reach inside a destination we do not own — ADR-080.
   */
  deliver(page: RenderedPage, cfg: DestinationConfig, idempotencyKey: string): Promise<DeliveryResult>
  /** Which arm is taken is read from `publications.made_live_by_us`, never from
   *  a re-read of the destination — ADR-081. */
  unpublish(pub: Publication, cfg: DestinationConfig): Promise<UnpublishResult>
  health(cfg: DestinationConfig): Promise<DestinationHealth>
}
```

## Out of scope

  `made_live_by_us` read that picks its arm — BP-048's, under BP-015's contract.
- **Deleting the `returned_to_draft` arm as dead code.** ADR-081's warning block

  the day that ability arrives the promise silently reverts to 'touch nothing'".
  The pin above exists so that cleanup fails.

- The danger-zone card and its typed confirmation input — BP-001's surface.
- Every sentence behind `danger.some_still_live` and `danger.all_taken_down` —
  BP-019's registry; the owner's words.
- Deleting content from the customer's own destination. REQ-079 non-goal: "a
  WordPress post ReachKit published is returned to draft, never deleted, and
  content ReachKit did not publish is never touched."

## Rollback
Delete two source files and four test files. Pages already taken down are not
re-published by a rollback, and must not be: REQ-079 c5 is explicit that nothing
in the system may release them, and the export is the only recovery path (REQ-079
non-goal).
