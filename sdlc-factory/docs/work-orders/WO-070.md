# WO-070 — The landing page — one text input, one submit, and nothing else

- Branch: wo/WO-070-landing
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-070.html
- Signed-off: 2026-09-03 — v1 — https://claude.ai/code/artifact/99a116b7-5305-4aad-84dd-3cff31bb3704

## Goal
Serve `/` as one text input and one submit control, with no other input of any
kind, no gate before submitting, and a written line in place when the value is
not a well-formed public domain name.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`.
> Placement per `structure.md`; `src/app/(public)/page.tsx` is BP-022's inside
> BP-001's `src/app/(public)/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(public)/page.tsx` | NEW | The landing page: one `Input`, one `Btn`, and the copy keys around them. The form posts to `/api/scan`. With JavaScript it posts JSON and navigates to `location`; without it, it is a plain form post that follows WO-062's 303. On a 422 or a returned problem handle it re-renders in place with the value intact and one written line from that handle's key. Reads no session, sets no cookie, renders no gate. |
| `tests/app/scan-address/landing.test.tsx` | NEW | The one-control, no-gate, error-in-place and no-JavaScript suites named in the test plan. |

## Interfaces

Consumes: WO-062's `POST /api/scan` and `StartScanResponse`; WO-051's
`DomainProblem` (type only, to key the written line); BP-019's `copy()`;
BP-018's `Input` and `Btn`.

Exposes (verbatim from BP-022 `## Public interface`):

```
Routes
  GET  /                                    landing: one text input, one submit, nothing else
```

## Steps
1. Produce the preview artifact at the path in the display bullets above and hold
   in draft until it is signed off (rule 7.3).
2. Write the failing suites first.
3. Render exactly one text input and one submit control. Render no select, no
   toggle, no checkbox, no radio, no second text field, optional or required.
4. Wire the JavaScript path: post JSON, then navigate to `location` on `ok: true`;
   on `ok: false` re-render in place with the value intact and the problem's
   written line.
5. Wire the no-JavaScript path: the same form as a plain post; WO-062's 303 to
   the canonical address on success, and its 303 back here carrying the problem
   handle and the value on failure, which this page re-renders in place.
6. Read no session and set no cookie; render no sign-in, no payment and no email
   field anywhere on the page.

## Test plan

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| REQ-001 c1 — "Given a visitor on the landing page, when the page renders, then it presents exactly one text input and one submit control and no other input control of any kind — no market, competitor, keyword or country field, selector or toggle, optional or required — and no sign-in or payment is required before submitting." | `landing/controls · exactly one input and one submit, and nothing else` — enumerate every form control in the rendered tree: exactly one text input, exactly one submit, and zero of every other control type; asserted structurally over the element list rather than by looking for known names, so a new field cannot slip past. And `landing/controls · no gate before submitting` — the page reads no session and sets no cookie, and the rendered tree contains no sign-in link, no payment control and no email field; a source assertion that `page.tsx` imports no auth or account module. |
| REQ-001 c3 — "Given a visitor who submits a value that is not a well-formed public domain name — an empty value, an IP literal, or a hostname with no public suffix — when they submit, then one written line names what is wrong with the value and the visitor stays on the landing page with their input intact. A well-formed domain is accepted here whether or not it resolves; a domain that cannot be reached is a failed scan (REQ-003), not a rejected input." | `landing/error · the line names the problem and the value survives` — for each of the three named cases, the page re-renders at `/` with exactly one written line resolved from that `DomainProblem`'s key and with the submitted value still in the input; the three lines are asserted distinct. And `landing/error · a well-formed unresolvable domain is not rejected here` — submitting one navigates to its report address rather than re-rendering with a line. |
| REQ-001 c2 — "Given a visitor who enters a domain in any of its written forms — with or without a scheme, with or without `www`, with a trailing path, in any letter case — when they submit, then they arrive at the single public report address for that domain; no two of those forms produce different addresses or different stored reports." | `landing/submit · every written form lands on the one address` — submitting each written form of one domain navigates to the identical canonical address; asserted end to end through WO-062's handler. |
| REQ-001 c3, the no-JavaScript half — "… the visitor stays on the landing page with their input intact." | `landing/no-js · the promise holds without a client runtime` — with scripting disabled, a valid submission follows the 303 to the canonical address and an invalid one returns to `/` with the line and the value intact; asserted against the server-rendered markup only. |
| REQ-001 c10 — "Given a visitor for whom a scan started under criterion 9, when they wait through it and read the report, then nothing is asked of them at any point between the domain they gave and the report they read — no account, sign-in, email address, or payment, and no further field. The finished page they may trade an address for afterwards is REQ-010's." | `landing/no-ask · nothing is asked on the way in` — the landing render and the navigation that follows a valid submission are asserted to present no further field of any kind before the report address is reached. The rest of this criterion is discharged at the report address by WO-069. |
| REQ-093 c1 (BP-022: "This node contains no string literal a person reads") | `landing/copy · every sentence is a key` — a source assertion that `page.tsx` contains no string literal rendered as text, and that every visible string resolves through `copy()`. |
