# WO-071 — deriveProfile — the nano profile call and the Measured<Profile> it returns

- Branch: wo/WO-071-derive-profile
- Estimate: ≤1 day

## Goal
Implement `src/lib/market/questions/profile.ts` so a domain's own home (and optional
pricing) text becomes a `Measured<Profile>` in buyer vocabulary through the single
`'profile'` nano call site, or an `unmeasured` result that yields no market set at all.

## Context an implementer needs
There is **no source code on disk** in this repository — `BUILD.md`, `DATA-COSTS.md`
and `sdlc-factory/` are the whole tree. Every path in the file plan below is
therefore NEW, and the placement is provisional against
`sdlc-factory/docs/registry/structure.md`, which gives `src/lib/market/**` to BP-011
and this file's directory to BP-025 (`code: src/lib/market/questions/**`).

## File plan

|---|---|---|
| `src/lib/market/questions/profile.ts` | **NEW** | Declares the `Profile` interface and `deriveProfile` exactly as BP-025's `## Public interface` states them. export interface Profile {
```ts
  category: string                      // buyer vocabulary, never the site's marketing language
  job: string
  offeringType: string
  audienceTerms: readonly string[]      // 2–4
  namedRivals: readonly string[]        // rivals the site itself names
  vocabulary: readonly string[]         // the relevance guard's support set
  brandTokens: readonly string[]        // the own-brand drop set
}
export function deriveProfile(c: CostContext, a: { home: string; pricing?: string }): Promise<Measured<Profile>>
```

## Steps
1. Create `src/lib/market/questions/profile.ts` with the `Profile` interface verbatim.
2. Declare the Zod schema for the model's output: the seven fields above, `audienceTerms`
   bounded to 2–4 entries. A response that does not parse is a failed call — BP-009's
   seam already returns `unmeasured` for it; add no rescue path.
3. Implement `deriveProfile` as one `llm()` call with `site: 'profile'`, `tier: 'nano'`,
   `input` = `{ home, pricing }` as handed in. Pass the `CostContext` straight through.
4. Return the `Measured<Profile>` unchanged. Do not synthesise a category, do not
   fall back to the site's own marketing wording, and do not retry.
5. Emit the observability field BP-025's `## NFR budget` names for this step: the
   profile outcome kind (`measured` / `zero` / `unmeasured` + reason).
6. Write the tests. Watch each fail before the implementation exists (constitution §8).

## Test plan
| Acceptance criterion (verbatim from REQ-006) | Test |
|---|---|
| 1. "Given a completed report, when the AI-answers card renders, then it states in writing how many of the market's biggest searches the report measured — twelve where the market yielded twelve, and the smaller number it yielded where it yielded fewer — states on how many of those an AI answer appeared, and shows every citation count on the card against those two numbers and never against a count of searches the report did not measure." — *contributing arm only*: an `unmeasured` profile yields no market set and no questions, so the denominator is what was measured and never a padded twelve. | `tests/market/questions/profile.test.ts › deriveProfile/unmeasured-profile-yields-no-value` — an `llm()` stub returning `{ kind: 'unmeasured', reason: 'undeterminable' }` is returned unaltered, with no `value` field and no substituted category. |
| 13. "Given any of the 12 questions, when it renders, then the search shown beside it (criterion 9) is the search that question was selected from, and how the question is worded never changes which search it stands for: a differently worded question is still the same measured search, and no question stands for a search the report did not measure." — *contributing arm only*: the profile is the relevance guard's and the own-brand drop's support set, and nothing else in this file may reach the model. | `tests/market/questions/profile.test.ts › deriveProfile/single-call-site` — exactly one `llm()` call is made, its `site` is `'profile'` and its `tier` is `'nano'`; no keyword or search term is passed in the input. |

Discrimination (constitution §8, mutation testing): deleting the `site: 'profile'`
argument, or replacing the `unmeasured` pass-through with a default `Profile`, must
fail a named test above. State that in the validation report.

Additional tests this WO owes its own file plan (not criterion-mapped; they guard the
